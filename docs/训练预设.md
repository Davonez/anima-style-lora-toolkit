# Next-Trainer 训练预设 v3 —— 用法说明

预设文件：`presets/anima-lora-style-v3.toml`

## 一、装法

1. 双击仓库根的 `安装预设.bat` → 选你的 Next-Trainer **根目录**（里面能看到 `config`、`sd-models`、`mikazuki`）；
2. 或者手动把 `presets/anima-lora-style-v3.toml` 复制到 `<Next-Trainer>\config\presets\`。

## 二、用法（3 步）

1. `安装预设.bat` 或手动复制。
2. 打开 Next-Trainer → 模型选 **Anima DiT**、引擎 **Kohya-ss**、目标 **LoRA**
   → 工具栏点 **训练预设** → 选 `Anima 画风 LoRA v3（rank32/alpha64 · 内容-only 标注）`。
3. 应用后，**只改两个框**（预设故意没写这两个，免得覆盖你上一轮的产物）：
   - **训练数据集路径** → 你的数据集目录
   - **模型保存名称** → 换成这次画师的名字
     **不改的话会和上一轮同名，直接覆盖旧的 `*_style-*.safetensors`。**

> 预设没出现在列表里？看 `[metadata] train_type` 是不是 `sd3-lora`
> ——GUI 用这个值过滤：只有等于当前页面的 schemaName 才显示。

## 三、为什么是这些数

| 项 | 值 | 依据 |
|---|---|---|
| rank / alpha | **32 / 64** | 缩放 0.5 时增量被砍半，只能靠把出图权重拉到 0.8~1.0 补偿，权重一高构图/动作就崩。改成 **2.0**，权重 0.4~0.6 就够。（代码依据：`networks/lora_anima.py` 里 `scale = alpha / lora_dim`） |
| 轮数 | **10 轮** | 632 张 × 10 = **6320 步**，落在 4000–7000 的目标区间。小集那套「40 轮」是给 34 张的曝光量，直接套到大集会过训练十几倍 |
| 存档 | 每 2 轮 | 出 2/4/6/8/10 五个档，够覆盖「60%–100%」的挑选区间 |
| 优化器 / lr | Automagic / 5e-5 | 学习率不必手调 |
| 调度 | cosine_with_restarts（1 cycle） | |
| keep_tokens | **1** | 把 `@触发词` 钉在第一位 |
| prefer_json_caption | **false** | 只有 `.txt` 时关掉，免得目录里冒出 json 被优先读 |
| resolution / 桶 | 1024,1024 / 256–1280 / 64 / 不放大 | 8GB 显存上比较稳的组合 |

时间：8GB 卡、1024 桶，约 **6~8 小时**。第一次跑还要额外建 latent + 文本编码器缓存，多花 10–20 分钟。

**换数据集时按这个换算**：步数 ≈ 张数 × 轮数，目标 4000–7000 步。
300 张 → 15 轮；800 张 → 8 轮。

## 四、出图权重：这次要往下调

alpha/rank 从 0.5 变成 2.0，等于同样的权重数字现在「浓 4 倍」。粗算：

| 旧（缩放 0.5） | 等效（缩放 2.0） |
|---|---|
| 0.8 | 0.2 |
| 1.0 | 0.25 |

但太低会被底模吃掉。**从 0.4 起测，0.4 / 0.5 / 0.6 三档各出一张**，
挑「风格到了、结构还没崩」的那一档。

## 五、清洗 → 训练之间的那个坑（必须做）

训练配置开着 `cache_text_encoder_outputs = true`，目录里会有 `*_anima_te.npz`。
这类缓存**只查键名、不比对 caption** —— 改完 txt 不清缓存，训练器继续用旧标注的 embedding，
**清洗等于没做**。

清洗器（`一键清洗.bat`）写盘后会问你要不要挪走这些缓存，选 `y`。
或者手动：把 `*_anima_te.npz` 删掉/挪走，`*_anima.npz`（潜变量）不用动。

## 六、GUI 会自动搬你的数据集目录（知道就行）

Next-Trainer 走 `--train_data_dir` 时，如果目录里没有 `数字_名字` 形式的子目录，
会把图片和 txt **一起搬进自动生成的 `N_zkz` 子目录**，N 由图片数决定：
≤10 张→7、11–50 张→5、51–100 张→3、**>100 张→1**。

- 600+ 张这套 → 生成 `1_zkz`，重复 1 次，步数就是「张数 × 轮数」，和上面算的一致；
- 但用 34 张那种小集时它会自动给 **5 次重复**，步数变 5 倍。
  想自己控制，就事先把图片放进 `1_xxx` 子目录，或者给页面挂一份 dataset_config。

## 七、跑完怎么评估

1. `一键对照.bat`：训练原图 vs 出图（或零权重 vs 挂 LoRA），出亮度/饱和/像素差报告；
2. 出图用清洗器生成的 `评测提示词.txt`（中立提示词，不含画风词），seed 固定；
3. 每档 ckpt 至少测 0.4 / 0.5 / 0.6；
4. 判据：**亮度差 <7 点（/255）、饱和差 <0.05** 且结构没崩，就是这一档。

## 八、常见症状 → 动作

| 症状 | 先查 | 动作 |
|---|---|---|
| 出图发黑白/发灰 | 数据集实测饱和（体检报告） | 数据集本身低饱和就认；不是的话加负向 `monochrome, greyscale, limited palette, spot color, sepia` |
| 动作/构图崩 | 出图权重 | 降到 0.4–0.5；还崩就是过训练，取更早的档 |
| 风格不够浓 | 轮数太短 | 加 4~6 轮重跑（别一上来加 rank） |
| 一换语言/一换提示词风格就没了 | 标注语言是否统一 | 跨语言不能假设泛化 |
| 改了标注没效果 | `*_anima_te.npz` | 挪走重训 |

## 九、想再进一步时（先别动）

- 觉得细节不够：**先加数据**（数据量是天花板），再考虑 `network_dim = 64 / alpha = 96~128`；
- 想让模型更依赖画面而不是文字：加 `caption_tag_dropout_rate = 0.05~0.1`；
- 想跑得快：把 `attn_mode` 清空让系统自动选 Flash Attention（装了就生效）。

以上都只改一个变量，跑完用对照工具量，别凭感觉。
